# Feature Specification: 可迭代契约与历史快照

**Feature Branch**: `codex/013-contract-refinement`
**Created**: 2026-10-04
**Status**: Accepted and deployed; real model/browser and22/22 isolated checks passed
**Input**: 用户要求微调真实进入契约、满意后单独构建，并可预览与恢复任意历史契约，复用发布历史交互，验证后同步 main 和部署。

## User Scenarios & Testing

### User Story 1 - 反复微调后确认构建 (Priority: P1)
用户在契约中输入修改，点击“继续微调”，看到完整的新契约；可以重复，最后点击“开始构建”。
**Why this priority**: 解决补充需求没有进入契约、旧排除范围与新要求冲突的问题。
**Independent Test**: 对真实生成的契约连续两次微调，核对新增要求与原要求保留，随后构建并实际操作生成的应用。
**Acceptance Scenarios**:
1. Given 已有契约，When 提交新增音效需求，Then 新契约包含该要求及对应检查，旧的音效排除项被修正，仍等待确认，没有启动代码构建。
2. Given 已有微调版本，When 再次微调，Then 基于当前版本修改并保留未要求删除的功能。
3. Given 用户满意且没有待提交文字，When 开始构建，Then 使用用户看到的确切契约版本；有未提交文字时提示先微调。
4. Given 微调失败、取消、超时或重启，Then 旧契约仍可阅读与恢复，错误真实显示，不能出现部分更新的新契约。

### User Story 2 - 预览与恢复历史 (Priority: P1)
用户浏览契约版本、预览完整内容并恢复选中版本，之后继续微调或构建。
**Why this priority**: 防止探索中的需求丢失，提供可追溯的选择。
**Independent Test**: 生成三个版本，预览第一版不改变当前内容，恢复第一版后刷新仍一致；后续版本仍在历史中。
**Acceptance Scenarios**:
1. Given 多个版本，When 浏览历史，Then 显示版本号、时间、修改说明及当前版本，提供预览与恢复按钮。
2. Given 历史预览，When 关闭预览，Then 当前契约保持不变。
3. Given 选中旧版，When 恢复，Then 完整需求、范围和设计说明恢复并形成新的历史记录；不会修改已发布网站或代码文件。
4. Given 其他用户或其他项目版本，When 读取或恢复，Then 拒绝且不泄露内容。

### Edge Cases
空白或超长输入；重复提交；跨标签页过期版本；微调中构建/恢复；无契约的旧项目；有契约但无历史的旧项目；历史分页；生成不合法或缺失检查；断线后刷新；取消与完成竞争。

## Requirements
### Functional Requirements
- **FR-001**: 微调与构建是两个独立动作；微调不会写应用代码。
- **FR-002**: 微调必须结合当前完整契约和修改说明，成功后一次性更新，失败保留旧版；生成的每项检查需符合独立浏览器上下文的执行规则。
- **FR-003**: 构建必须采用当前确认版本，历史说明不能覆盖所选版本；拒绝过期操作。
- **FR-004**: 初次完成、每次成功微调和恢复均保留持久化快照，包含需求、检查、范围、设计及修改来源。
- **FR-005**: 历史支持分页、只读预览及恢复；恢复追加新版本，不删除过去记录。
- **FR-006**: 所有读取与变更限定项目所有者；错误、忙碌和重试状态可理解，重复请求不得重复变更。
- **FR-007**: 原项目已有契约保留为历史起点，不伪造此前不存在的历史；不影响代码和发布历史。
- **FR-008**: 发布与契约历史保持一致的列表、预览和恢复交互。
### Key Entities
- 契约版本：项目、版本号、完整内容、修改说明、时间、来源版本。
- 微调任务：基准版本、用户输入、运行状态与错误。
- 确认构建：确认的契约版本及执行记录。

## Success Criteria
### Measurable Outcomes
- **SC-001**: 真实模型连续两次微调，新增要求均在可见契约和最终构建中生效。
- **SC-002**: 任意历史版本可完整预览、恢复并在刷新后保留；恢复不丢失后续历史。
- **SC-003**: 失败、取消、重复与过期请求测试均保持契约一致性和项目隔离。
- **SC-004**: 桌面与移动端通过真实浏览器操作验收，无页面异常；部署后健康、版本与关键流程验证通过。

## Assumptions
- 沿用项目的所有者认证、规划模型、运行时和计费机制；微调涉及真实模型调用。
- 已生成项目可微调契约并重新构建；恢复本身不回滚代码或网站。
- 自动检查不能证明所有体验质量；音效还需检查真实音频行为，不能只以文字或按钮存在认定通过。
