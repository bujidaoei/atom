# Publication experience contract
Checks: successful POST saves actual complete results and returns UTC timestamps; infrastructure errors are distinct from failed assertions. Old results are not current proof.
Publication: owner-only mutations carry idempotency identity and expected saved revision/live generation. Default policy permits absent/failed optional functional checks; ownership, exact artifact integrity, content policy and independent delivery remain mandatory.
History: bounded newest-first retained publications ordered by their committed publication generation; current online marker, published time, preview and restore capability. Display names are human-readable, identifiers diagnostic only.
Restore: exact retained content, atomic generation change and durable new history event; draft is unchanged. Missing content or stale generation does not disturb current public content.
Unpublish: public access removed, history retained. No external data rollback is implied.
Precise versioned wire/schema extension is completed in T004 before US2 coding.

## Versioned policy design (T004)
Schema16 follows exact schema15 only and rebuilds release_records within the existing protected offline migration transaction. Preserve IDs, pointers, content bindings, command receipts and rollback source rows. Add verification_mode (advisory|required); make verification_id, contract_digest and verifier policy_digest nullable as one group. Existing rows retain their evidence and become required. Advisory rows carry no invented verification; strict rows retain passed attestation requirements. Add direct revision/workspace/project scope constraints because nullable composite verification FKs do not enforce revision identity. Preserve immutable-row triggers. The rollback source trigger uses NULL-safe field comparisons and conditional evidence requirements. Never rename the old table first, which could rewrite inbound foreign keys.

POST /projects/{id}/releases retains releaseId, expectedRevision, expectedGeneration, audience and slug; verificationId is required only under server-configured required policy. The client cannot choose a weaker policy. Advisory must not depend on verifier configuration, require a valid functional contract or imply verified status. Both modes reuse preflight bytes/hash/size/content-policy validation and transactional owner, idle/head, generation checks. Intent digests include resolved mode; conflicting replay fails. Release row, binding, live pointer, receipt and audit event commit atomically.

GET current returns nullable verificationId plus explicit verificationMode and human-readable display metadata. History is owner-scoped, stable keyset pagination by publication_generation, bounded page size, retained snapshot identity, timestamp, live marker, restore origin and optional verified state. The history preview action obtains existing private-content access for a retained binding rather than exposing mutable workspace files.

Chronology refinement: schema16 stores each release's immutable publication_generation, unique per project. Protected migration recovers it from the existing publish/restore command receipt and rejects missing or mismatched evidence rather than guessing from timestamps or random IDs. New records must equal the current pointer generation plus one within the publication transaction. Unpublish advances the pointer but does not create a snapshot, so displayed version numbers may have gaps. History sorting/pagination remains correct across equal timestamps and a backward wall clock; retention of audit event payloads does not affect this identity.

POST restore creates a new release/binding and rollback provenance from retained bytes under the CURRENT server policy. Advisory can restore advisory or previously verified content without pretending a new verification occurred. Required mode demands eligible source evidence; never upgrades advisory content silently. Preserve expected live generation and draft-head concurrency guards. Draft remains unchanged. Missing/corrupt bytes, stale head or policy mismatch leaves live pointer intact.

Schema16 consumers must be reviewed individually: migration and backup verification, schema_guard, RevisionRepository, VerificationRepository, VerifierAuthority, release/content/access repositories, content entry, audit branches, deployment preflight and CLI. Preserve old-schema test support; do not globally substitute version tuples. Mandatory tests: required+NULL denial, cross-project revision denial, forged evidence, NULL advisory restore, source identity preservation, failed migration recovery, owner isolation, old-binding revocation, idempotency and concurrent promotion.

COS storage port uses put(bytes)->Artifact and read(contentHash)->bytes. Keys remain SHA256-bound, snapshots verified before write and after read. Dedicated prefix, private object ACL, HTTPS endpoint and no credential diagnostics. Imported local artifacts must be byte-verified in COS before switching authoritative reads. No runtime fallback that silently publishes stale local content. Storage selection is explicit; independent content site remains separate from private COS origin.

Restore design refinement: schema16 permits restoring the most recently unpublished snapshot (source may equal displaced). A new release identity is still required. Advisory restoration can proceed with a failed idle draft, since it uses retained published content; active runs/attempts and changed draft/live generations still reject the request. Original strict pre-v16 semantics remain covered. History preview after unpublish requires a newly authenticated owner capability at the current generation, never reuse of pre-unpublish public/private authority. A bootstrap challenge may be allocated for a retained binding but carries no content authority; owner/source checks precede handoff, exchange and every private read. This repository behavior is implemented; actual browser/ingress acceptance remains open.

## IP-only URL contract (gated implementation)

When the paired IP mode is active, current public release URLs are the project's immutable `https://IP:public-port/`, independent of publication generation, restore and slug. Owner-only releases do not receive a public URL. Retained history does not return a reusable private-content URL; the owner clicks Preview to issue a one-use, exact-revision capability on the project's preview port. A missing port pair fails publication before mutation. The console's legacy `/p/{slug}` path redirects only a currently live public release to that project's public port, retaining safe subpaths and bounded query strings; withdrawn, private or unknown slugs do not serve generated HTML. This implementation is not a production-activation claim: an ingress probe and atomic rollback are still required.
