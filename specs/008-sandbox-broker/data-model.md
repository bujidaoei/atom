# Entities and states
Grant v1: jti, organization/project/run/attempt IDs, positive fencing integer, base_revision SHA-256, profile files-v1, issued-at/not-before/expires integer timestamps, fixed issuer/audience/subject/type. Validity requires issued-at ≤ now < expiry, nbf=iat, bounded original lifetime. Immutable claims; no host path, secret, image, resource flag or arbitrary capabilities.

Registry (planned): versioned schema; grant ID unique; canonical claim digest; organization/project/run/attempt/fence; base revision; deadline; owned container name; state; latest checkpoint; termination outcome; revoked flag; operation receipt IDs. Token/key material never persisted.
Registry v3 implements broker_meta, attempts, heads, revocations, orphans and operations per contracts/registry.md and contracts/operation-receipts.md. Exact v1/v2 upgrades atomically preserve existing history and add missing tables. Revocation is a durable tombstone table, not a boolean column; confirmed/unknown termination is explicit state. Orphan observations have immutable container ID, claimed attempt ID, observed/termination_unknown/terminated state, version and timestamps; they never manufacture a grant, normal attempt or accepted revision. Operations retain request hashes, admission version, bounded response reservations, completed results and running/completed/unknown state. Read results contain workspace data and require private storage; this is not an encrypted retention system. A checkpoint digest in the registry does not itself register an accepted control-plane revision.
States: intent→provisioning→ready→quiescing→checkpointed; administrative termination interrupts nonterminal states through terminating→terminated/termination_unknown. There is no registry failed state. Unknown outcomes require reconciliation before renewed dispatch. Cancel/revoke forbids new operations immediately. Registry receipt is not control-plane authority; registration must use current execution fence.

Seed lifecycle uses the existing provisioning intent and immutable base_revision; no schema migration is needed. A fixed helper validates and promotes the archive before the current-version ready transition. A crash leaves either provisioning (retire on recovery) or durable ready (also retired on process restart under current recovery policy). No snapshot revision is registered by seed. Repeated seed against ready is rejected without effects; trusted provision/status resolution can observe ready for the same immutable grant.

HTTP authority does not add persisted entities: administrative seed uses a read-only provisioning authorization check, and scoped file requests reuse the existing receipt identity and current ready attempt. Transport admission is process-local and bounded to one active transfer; it does not replace durable lifecycle state or support multi-process ownership.
