# Structured file operations v1

No caller-supplied command/script/environment/root. Broker selects a fixed Python helper, running nonroot inside the already-owned files-v1 container, with JSON over stdin. Typed operations: read_bytes(path), read_lines(path,start,limit), glob(pattern,limit), grep(pattern,path,glob,case_sensitive,limit), write(path,content,expected_sha256 optional). Exact keys/types/bounds; defaults belong to adapters, not ambiguous wire requests. Root is fixed /workspace. Pi remains unchanged; own wrappers will translate into these operations in a subsequent T007 step.

Path policy: relative NFC POSIX paths, no empty/dot/parent segments, backslashes, control characters, Windows device names, reserved .git/.pi/node_modules/__pycache__/.env* entries; 1024 UTF-8 bytes and 32 segments. Grep base may be '.'. Descriptor-relative O_NOFOLLOW traversal/open rejects symlink/hardlink/nonregular files. Search never traverses symlinks, skips reserved trees and bounds visited entries at 16384. Glob matches full relative paths with segment-aware *, ?, [] and ** (zero or more segments), including nonreserved dotfiles. Limit 1…500; grep regex 2000 characters, one-MiB candidate files, read_lines starts 1…10000000 and returns 1…5000 lines. UTF-8 replacement decoding matches existing text tools; read_bytes preserves exact bytes as base64. Text results retain '(no matches)'/'(empty range)' markers, max 256 KiB; overflows fail explicitly rather than reporting complete results.

Files max 8 MiB (snapshot format limit); strict JSON input max 50 MiB and response max 12 MiB accommodates worst-case escaped text/base64 without command-line content. Write uses same-directory exclusive temporary file, fsync and descriptor-relative replace; optional expected_sha256 requires current bytes to match before mutation (future Edit CAS). Helpers hold an exclusive flock on the workspace directory for the operation, including conditional read/replace; concurrent cooperating helper writes cannot both win the same expected hash. This is not a lock against future arbitrary workload processes. Writes reject casefold collisions in existing ancestor/target names. No automatic retry of writes. Hash and byte count are returned; successful helper response is a file effect, not a registered snapshot/revision. Parent directory creation may persist after a failed write; prior file content is preserved. Hard-killed helper temporary files require retirement/reconciliation, not snapshot publication.

Grep searches only its selected file/subtree. Its optional glob retains the existing PurePosixPath.match suffix semantics (for example '*.txt' includes nested text files); the separate Glob operation uses full-path segment matching. Grep checks accumulated output bytes before retaining each matching line. No clipping is reported as complete text.

Helper has an independent SIGALRM deadline, including stdin read/regex, on Linux. Broker subprocess timeout/output limits remain separate. Killing Docker CLI is not proof a remote exec stopped; helper errors/transport uncertainty require lifecycle retirement before other writes in T006 integration. Initial driver adapter accepts only ready, owned, running attempts and revalidates effective profile. It is a trusted internal component, not runtime authorization: grant verification/state/fence/serialization/receipts belong to lifecycle/HTTP integration. No file HTTP route until those are complete.

Tests must run actual helper in restricted Docker containers: binary/text ranges, recursive glob/grep, atomic writes/CAS mismatch, paths/link/FIFO/hardlink refusal, quotas, malicious regex deadline and peer survival. Pure schema tests alone cannot close T007. Runtime wrapper migration, cancellation, receipts and snapshot seed remain open until separately demonstrated.

Runtime port migration: SandboxClient exposes an optional structured fileOperation capability; file tools require it and fail closed if absent, with no exec fallback. Exec remains a distinct capability for existing explicitly enabled command workflows, never synthesized by file wrappers. File requests carry toolCallId plus the operation union; results carry correlated ID plus text, binary/hash, or written-size/hash. Wrappers validate correlation/types/bounds and read/write digests before accepting responses. Policy guards still run before dispatch. Pi Read retains image/range behavior; Pi Edit caches one read per path and supplies its hash for conditional write. Group sandbox decorators must forward the structured capability.

Local development adapter remains explicitly non-isolated. Native bounded byte reads/atomic writes and per-workspace serialization implement structured operations; its fixed Python text/search helpers may use the existing development subprocess runner. Those scripts live only in the development adapter, never the product file-tool wrappers or broker input. This preserves Python regex behavior without substituting JavaScript regex semantics. Local execution does not claim the Linux broker's descriptor/isolation guarantees. Production selection remains T008.

HTTP admission is now implemented in service.py under runtime-http.md: lifecycle receipts, grant checks and verified snapshot seeding are real component paths. Fixed helpers alone still do not grant authority. Runtime wrappers have migrated to the structured port; their actual use through the new HTTP broker is the remaining integration gate, along with checkpoint registration and production selection.
