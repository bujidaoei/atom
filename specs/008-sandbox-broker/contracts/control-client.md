# Trusted control-plane broker client

The Python client is owned by the control plane, never shipped in a runtime lease. Explicit origin/admin credential/signing codec and finite whole-request timeout are required. Allow HTTPS origins or literal HTTP loopback only; reject user information, query, fragments, nonroot paths, ambiguous hosts and redirects. Ignore proxy/environment authentication. No automatic retries or fallback execution. Exceptions expose stable codes/status only, never tokens, bodies or transport details.

Provision/seed check exact reply schema, broker ID, state and grant deadline. Seed verifies complete archive/base before network effects. Export reads a bounded uncompressed byte stream and checks exact metadata headers, attempt identity, canonical positive version, archive digest and semantic snapshot digest. Do not materialize host workspace files. Confirmation requires a trusted API Receipt whose control attempt and artifact/revision match the grant and export; this is a shape/binding guard, not an independent API-database lookup. The coordinator must obtain the receipt from RevisionRepository. Verify the exact confirmation reply and expected version increment. Revoke uses independent administrative authority so cleanup can be requested after grant expiry; accept only confirmed terminated or not_admitted results.

The request deadline includes connection, upload and complete response read; successful HTTP headers alone are insufficient. Unexpected responses, malformed/oversized content, timeout or cancellation cannot fabricate success. Non-success HTTP status is reported without its body; side effects may already exist and coordinator reconciliation/receipt lookup is required. Configuration is not an authorization decision for projects or organizations. Production lease orchestration, durable reconciliation, API startup selection and runtime completion remain open.
