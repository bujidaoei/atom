# Control-plane registration requirements (not implemented)

Current API evidence: models.py Project has active_run_id/event_seq; Run has project_id/heat_id/status but no durable attempt/fence. db.py initializes SQLite and main.py uses schema_guard plus create_all; there is no versioned migration runner. Do not infer revision authority from these fields or from broker-local state.

Required migration must preserve existing projects/runs/events and mutable workspaces until verified import, record an explicit schema version, reject unknown versions, support consistent backup/restore and transactional rollback, and never silently reset data. Main project workspaces and race heat workspaces need distinct durable revision heads; a heat must not overwrite the main project head. Existing projects have no accepted snapshot until their actual bytes are imported and verified. No invented empty revision is a migration default.

Required execution ownership binds project/workspace/run/attempt, a monotonically increasing generation, exact base revision, deadline and terminal/cancel status. Tenant/membership authority must come from implemented project/organization relationships, never a caller-supplied organization string. Registration uses the persisted ownership mapping rather than trusting a destination supplied by runtime. A broker fence is subordinate execution evidence, not the database project commit authority.

Required commit sequence: persist an immutable verified artifact, then in one database transaction recheck current run/attempt/generation/deadline/cancellation and expected base head; insert a scoped immutable revision and atomically advance that workspace head with its audit/outbox evidence. Exact replay of the same attempted registration returns the original receipt; changed artifact or stale generation conflicts. Never perform Docker/network/filesystem IO inside that transaction. A stored but unreferenced object after a crash is not a registered revision; do not delete it without reference-aware recovery.

Only after durable registration acknowledgement may broker state become checkpointed and normal runtime completion release the worker. Lost acknowledgements require receipt lookup, not a new version or success inferred from export. Failed registration preserves the prior head. Preview/publication must consume committed revisions, not live worker bytes. These requirements are T009/T010 and parent execution/collaboration gates; artifact storage tests alone do not complete them.

Primary-source check for the upcoming SQLite migration (2026-10-01): SQLite documents a single simultaneous writer and BEGIN IMMEDIATE acquiring write ownership before later statements; busy/IO failures must not be interpreted as a completed migration. Its Online Backup API provides a consistent database snapshot and is preferable to an uncoordinated file copy of an active database. Migration must explicitly bound lock waits, roll back failed changes and verify restore before production use. These are design requirements, not an implemented backup/migration claim. Sources: https://www.sqlite.org/lang_transaction.html ; https://www.sqlite.org/backup.html .
