# Control-plane registration requirements

Current API evidence: models.py Project has active_run_id/event_seq; Run has project_id/heat_id/status but no durable attempt/fence. Offline API migration v1 now creates separate revision authority tables; startup does not invoke it. Do not infer revision authority from legacy fields or broker-local state.

Required migration must preserve existing projects/runs/events and mutable workspaces until verified import, record an explicit schema version, reject unknown versions, support consistent backup/restore and transactional rollback, and never silently reset data. Main project workspaces and race heat workspaces need distinct durable revision heads; a heat must not overwrite the main project head. Existing projects have no accepted snapshot until their actual bytes are imported and verified. No invented empty revision is a migration default.

Required execution ownership binds project/workspace/run/attempt, a monotonically increasing generation, exact base revision, deadline and terminal/cancel status. Tenant/membership authority must come from implemented project/organization relationships, never a caller-supplied organization string. Registration uses the persisted ownership mapping rather than trusting a destination supplied by runtime. A broker fence is subordinate execution evidence, not the database project commit authority.

Required commit sequence: persist an immutable verified artifact, then in one database transaction recheck current run/attempt/generation/deadline/cancellation and expected base head; insert a scoped immutable revision and atomically advance that workspace head with its audit/outbox evidence. Exact replay of the same attempted registration returns the original receipt; changed artifact or stale generation conflicts. Never perform Docker/network/filesystem IO inside that transaction. A stored but unreferenced object after a crash is not a registered revision; do not delete it without reference-aware recovery.

Only after durable registration acknowledgement may broker state become checkpointed and normal runtime completion release the worker. Lost acknowledgements require receipt lookup, not a new version or success inferred from export. Failed registration preserves the prior head. Preview/publication must consume committed revisions, not live worker bytes. These requirements are T009/T010 and parent execution/collaboration gates; artifact storage tests alone do not complete them.

## Repository implementation contract
Committed read contract: current_revision(owner, workspace) returns the current immutable revision identity plus its stored artifact metadata under owner scope, or None for an uninitialized workspace. It performs no head/attempt changes. A trusted materialized_revision view reads that exact content-addressed object, verifies byte size and semantic revision, and extracts to a private temporary directory using the existing verified receiver. It never reads or overwrites the mutable legacy workspace. The captured revision stays stable if the head subsequently advances; its temporary directory is removed on normal exit and exception. Callers must use the returned revision ID when reporting which bytes were checked. This is a read/validation prerequisite, not preview route cutover or product acceptance.

Application startup contract: production API selects broker execution with explicit origin, private artifact directory and three distinct administrative/grant/completion secrets, separate from session/runtime/model credentials. Require offline-migrated schema; never auto-migrate or create an empty broker database. Hold a nonblocking Linux process lock on the existing database inode throughout startup, request admission and shutdown. Construct storage/client/coordinator, reconcile before readiness and mount exact execution completion/cancellation routes. Shutdown withdraws readiness, stops orchestration and reconciles while still owning the database, then closes client and releases the lock. Duplicate ownership, unsupported platform, unsafe database, invalid configuration and recovery failures deny startup. Protected database directories must not be replaced by administrators while running. This host-local lock is not HA coordination. Main scheduling/lease delivery and immutable preview adoption remain separate gates.

Initial import contract: a trusted offline caller supplies an absolute, quiescent workspace directory after stopping legacy writers. Resolve owner/project/heat identity before file reads; export the actual directory with the existing bounded Linux snapshot verifier, persist the verified archive before bootstrap, and return immutable artifact and root revision identity. Do not accept model-supplied filesystem paths. Reject roots containing the API database or artifact store. Repeating unchanged import returns the same root; changed source conflicts without resetting the head. Failed storage/registration never implies an imported revision; an unreferenced immutable object may remain for future audited retention. This operation neither stops writers itself nor switches preview/runtime paths.

Workspace identity contract: ensure_workspace(owner, project, optional heat) checks current project ownership and heat membership through its race before looking up or creating identity, within one finite write transaction. Concurrent retries return the same generated logical ID. Existing identity, head, generation and active attempt remain untouched. A new row has no revision or artifact; real verified import is a separate bootstrap operation. Invalid, missing and foreign scopes cannot create rows. This internal operation does not yet wire project routes, import files or authorize dispatch.

Terminal decision contract: before administrative release, persist the intended outcome using existing nullable outcome with nonclosed state. This is a decision, not completion: only closed/confirmed proves a terminal result. A pending decision denies dispatch/completion re-entry and retains the active slot. Success decision requires current completion authority and an existing receipt, after actual broker acknowledgement in the coordinator. First decision is stable across failed retries; explicit cancellation may override any nonclosed decision. Unknown termination preserves the decision. Restart reloads it and repeats exact-grant revocation before confirmed closure, including after expiry; absence alone is never success evidence. No schema change is needed because v1 already allows nonclosed outcome values. Consumers must interpret outcome together with state/termination_state.

Completion coordinator contract: completion reads retain owner/current-run/generation/deadline/active checks, but permit the head to equal that attempt's immutable receipt revision after registration. They never reauthorize file dispatch. The coordinator quiesces/exports, stores verified bytes, registers exactly once, confirms the checkpoint, revokes and records success only after confirmed termination. Receipt recovery before broker acknowledgement may re-export the quiesced worker and exactly replay registration; after broker acknowledgement a signed/admin-authorized read-only status query must match the receipt digest before skipping export. Closed completion replay preserves the recorded outcome. Storage/registration/confirmation failure never implies success and preserves any already committed receipt. Unknown release retains ownership. Completion and preparation share one finite local admission lock; cancellation bypasses it. Durable scheduling and runtime Run status adoption remain separate gates.

Preparation coordinator contract: prepare consumes an already committed reservation, reads/verifies its actual immutable base outside the database transaction, reconstructs the exact persisted grant, rechecks dispatch, provisions, binds the returned identity, seeds only provisioning workers, and rechecks dispatch before returning a ready runtime lease. Ready replay must not reseed. The lease exposes only scoped bearer authority, never administrative/signing credentials, and excludes its token from repr. A single coordinator serializes preparation through a finite three-second admission wait; cancellation bypasses it. Failures after authorized entry revoke the exact grant and close failed only after confirmation; caller cancellation uses cancelled closure. Unknown cleanup retains the slot. Multi-process scheduling/ownership, durable owner-namespace transfer and application integration remain deployment gates; this component is not a distributed scheduler.

Cancellation coordinator contract: `ExecutionCoordinator.cancel(owner, attempt_id)` commits the repository cancellation before issuing administrative revoke of the returned exact grant. An already closed result is returned unchanged without another network request. Only the client's verified terminated/not_admitted response permits confirmed cancelled closure. Transport/protocol errors or coroutine cancellation attempt to persist unknown termination and retain the active slot, then propagate the error/cancellation. Concurrent confirmed closure is preserved, including its original outcome and receipt. Repository failure cannot be interpreted as release; all SQLite calls occur outside the event loop through bounded repository operations, never across a network-await transaction. No automatic provisioning retry or new attempt is part of cancellation. This internal coordinator method does not expose a runtime endpoint or synchronize legacy Run status.

Recovery contract: an owner-checked `recovery` query returns the persisted attempt/grant/broker identity, deadline, state, termination observation, outcome and optional registration receipt in one SQLite snapshot. It remains available after expiry, cancellation, registration, run replacement and confirmed closure; it neither authorizes dispatch nor changes the head, active slot, generation or outcome. Do not include grant issuance/base/fence inputs in this cleanup view. `cancel` commits cancellation and returns the same recovery view atomically; repeated cancellation of a closed attempt preserves its recorded outcome. The coordinator must revoke that exact grant and obtain real termination evidence before closure. Read recovery information does not mean it is still current when an external request completes; mutations retain their own transactional checks. Project ownership is rechecked on every query, including closed attempts; ownership transfer reconciliation remains a separate policy gate.

Reservation/binding contract: replace the post-provision allocate operation with reserve, which commits owner-checked run/workspace/base/generation/grant/deadline and original issued_at (existing created_at) before any worker request. broker_attempt_id starts null, as supported by schema v1. Return persisted project/base-artifact/semantic-revision fields for exact request reconstruction; retries preserve issued_at and generation. Only a fresh active/current reservation may be loaded for dispatch. Binding requires the same current owner/run/head/fence/deadline and atomically fills the broker ID once; exact active replay is idempotent and changed identity conflicts. Unbound reservations cannot register output. Cancelled/expired/uncertain reservations cannot bind or be replaced until actual administrative revocation/termination (including not_admitted tombstone) is confirmed. No worker request or network IO occurs in repository transactions.

Production coordinator must preserve its authorized personal-owner namespace; ownership changes invalidate dispatch and require cancellation/reconciliation, not minting a different grant for the same ID. Organization/team transfer policy and durable coordinator scheduling remain open. Component integration must demonstrate reservation before creation of its target worker; the separate test storage container is infrastructure setup, not that target execution.

Trusted internal repository operations use an explicitly migrated database and persisted Project.user_id ownership, not a supplied organization identity. They must not be exposed directly to runtime. Every mutation uses a finite-wait BEGIN IMMEDIATE transaction, checks schema v1 and current ownership, and performs no filesystem/network work beyond SQLite itself. Artifact descriptors are accepted only from trusted immutable storage orchestration; descriptors alone are not proof of physical durability. Linux integration must exercise real ArtifactStore.put before registration.

Bootstrap records an actual verified artifact as the one root for an empty workspace; exact repeated bootstrap returns that root and changed bytes conflict. Reserve persists a caller-generated stable attempt/grant ID, run, workspace, current base and monotonically increasing generation; bind later attaches the broker ID. Run must be running and the current Project.active_run_id or heat.run_id. Only one active attempt is allowed, including an unbound reservation; confirmed termination must clear it before replacement. Deadline is an integer epoch in the next 7200 seconds. Exact reservation retry retains the same issuance time/generation; changed parameters conflict.

Register resolves the destination from the attempt, compares broker/grant binding, active attempt, generation, expected base head, running/current run, deadline and cancellation under the same transaction. It inserts verified artifact metadata, immutable revision, exact-request receipt and outbox event, then advances the head atomically. Exact receipt replay remains readable after cancellation, expiry, termination or a successor; replay never changes the current head. Changed registration conflicts. Ownership is checked even on replay. Bootstrap creates no runtime-registration receipt/event.

Cancellation is durable and rejects later first-time registration. Trusted coordinator termination observation is separate: unknown termination retains the active slot and cannot claim success; confirmed closure records the outcome and clears only that exact active attempt. Success requires an existing registration receipt. Cancelled/failed/timed-out closure may preserve an existing receipt: later failure must neither erase a committed revision nor manufacture a successful run. Registration proves durable snapshot integrity, not independent product acceptance. These internal observations do not themselves inspect Docker or update legacy Run status. Future orchestration must obtain real broker evidence before reporting confirmed termination. Outbox delivery and full application integration remain separate uncompleted work.

Primary-source basis (2026-10-01): SQLite documents a single simultaneous writer and BEGIN IMMEDIATE acquiring write ownership before later statements; busy/IO failures must not be interpreted as a completed migration or revision commit. Its Online Backup API provides a consistent database snapshot and is preferable to an uncoordinated file copy of an active database. Offline migration now implements bounded lock acquisition, verified backups and rollback/restore tests; this is not production migration acceptance. Sources: https://www.sqlite.org/lang_transaction.html ; https://www.sqlite.org/backup.html .

Startup recovery contract: trusted pending_executions enumerates nonclosed attempts joined to current project owner, ordered by created_at/id, returning only cleanup identifiers. Validate an integer limit of 1–1000 (default 100); refuse over-capacity before returning a partial list. It grants no dispatch authority. ExecutionCoordinator.reconcile holds local preparation/completion admission, obtains the inventory, stops each exact grant through existing durable decision/confirmed-release ordering and requires a final empty inventory. Default interrupted outcome is failed; existing success/cancel/timeout decisions survive. A finite timeout (default 60s, maximum 300s) cancels transport and performs existing bounded unknown-state persistence; cleanup/database lock time can extend the wall-clock timeout. Caller must hold exclusive scheduler ownership before invocation and withhold new work until success; this is not a process lease or distributed scheduling. Legacy Run synchronization remains separate.

Committed HTTP contract: broker-mode preview and text-file routes resolve existing workspace identity without creating rows, under current owner/project/heat scope. Materialize one verified revision at a time per API process with a three-second admission wait. Consume bounded file bytes before closing the private view; response headers include X-Atom-Revision and Cache-Control:no-store. Foreign/missing scope returns 404, unsafe preview path 403, unavailable/corrupt/busy storage 503, with no legacy fallback. Preview draft access requires ownership; publication remains a separate route. Multi-request browser revision pinning, origin isolation, file-list serialization and publication/race adoption remain separate gates.

Committed catalogue contract: authenticated project routes supply an explicit catalogue callback to serializers in broker mode; missing callbacks must not silently select legacy storage. Reuse the bounded revision-read slot and verify artifact bytes/size/semantic digest before using manifest path/size/SHA-256 entries. Return revisionId and index-first stable ordering. updatedAt is the immutable revision registration timestamp with timestampSource=revision, not a source-file mtime. Missing initial workspace/head yields empty files with null revision; corrupt/unavailable artifacts fail 503. Race file counts/bytes and index preview availability use the same per-heat verified catalogue. This does not migrate persisted run/event statistics or publication/race adoption.
