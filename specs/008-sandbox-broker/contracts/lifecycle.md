# Lifecycle coordinator — staged implementation

Only one process may control a broker registry. An OS file lock in the private registry directory is held for the coordinator lifetime and released by process exit; do not delete/recreate its inode. A bounded in-process lock serializes control operations. The future HTTP service must run one broker worker, invoke startup reconciliation before readiness, and schedule periodic sweeps. Runtime/admin authentication remains T004.

Startup retires all previous nonterminal attempts: persist revocation/termination intent, verify Docker removal, then persist confirmed termination. It does not resume unverifiable in-flight writes or preserve uncheckpointed tmpfs. Subsequent work requires a new grant/fence and committed input revision. Duplicate provisioning within one coordinator reuses the same container. Provisioning returns provisioning state; no ready/file execution claim until input snapshot import is integrated in T009.

Revocation tombstone is persisted before waiting for the control lock; callers immediately lose subsequent authorization. Driver failure while stopping persists termination_unknown, lowers readiness and blocks new provisioning. Successful later reconciliation may restore readiness after confirming all unsafe attempts are gone. Creation failure triggers explicit termination reconciliation, never silent replacement. A missing/exited active worker is retired, not recreated.

Startup/sweep compares Docker's broker-labelled inventory against registry ownership. Initial T006 implementation fails closed on missing registry records or contradictory terminated records; durable orphan observation/import and safe cleanup must be added before T006 is marked complete. No unknown container is deleted solely from a name. This staged boundary prevents false readiness while recovery evidence is incomplete.

Known-resource tests: real process-lock contention, actual Docker cancel and duplicate provisioning, abrupt broker process exit followed by retirement, lost create response injected after real creation, and unreachable Docker daemon causing durable unknown termination/no new dispatch. Lease acquisition, lock waits and reconciliation batches are bounded. Worker independent TTL remains a fallback, not proof of immediate cancellation. File-helper in-flight serialization and durable operation receipts remain T007/T006 integration work.
