# Broker service v1 — control operations

Separate FastAPI application, no import of API settings/database and no module-import resource creation. Configuration requires absolute private registry path, local pinned image ID, independent 32–128 printable ASCII admin credential and grant-signing key. Reject equal secrets and known development placeholders. Environment input is explicit ATOM_BROKER_*; no dotenv discovery or generated fallback. The supplied entry point binds literal loopback, one process, no proxy trust/access logs. External access requires a separately validated TLS deployment; it is not enabled here.

All implemented routes require one exact Authorization: Bearer admin credential, constant-time comparison. A runtime grant is never administrative authority. GET /health returns liveness/readiness; GET /ready returns 503 until reconciliation and pinned local image validation succeed. Image unavailability must not prevent old-resource cleanup. POST /v1/admin/provision accepts exactly {"grant": signedToken}, validates signature/time/schema before any lifecycle call, and returns 202 with attempt ID, state=provisioning and deadline. This prepares a real container; it does not claim imported/ready workspace. POST /v1/admin/revoke accepts exactly {"grant_id": logicalID}, persists cancellation and confirms cleanup; absent attempts still persist replay-denying tombstones. No shell, file, snapshot or revision endpoint is exposed until implemented.

Authenticate before consuming bodies. JSON only, no content encoding, 12 KiB maximum streamed body and five-second read deadline, reject duplicate keys/non-finite values/extra fields/type confusion. Stable redacted errors never include credentials, raw bodies, SQL or container details. Authentication failures return 401; malformed bodies 400/413/415/408; invalid grants 403; ownership conflicts 409; unavailable/busy lifecycle 503. Denied authentication/schema/signature requests have no request-induced registry/driver effects; independent maintenance is separate.

Lifespan acquires the process lease and performs initial reconciliation. Recoverable reconciliation failure keeps service alive but not ready; periodic sweeps retry serially with a stop event and configured finite interval. Normal shutdown stops scheduling, awaits any ongoing sweep and runs confirmed cleanup without cancelling the maintenance task. Forced process termination/cancelled server shutdown relies on persisted recovery and independent TTL, not this normal-shutdown guarantee. Existing bounded driver calls/registry locks/batch size bound each sweep, not a promised five-second cleanup SLA. Unexpected maintenance errors lower service readiness and are redacted; no unobserved background task failures. File-operation serialization and overall production deadlines remain T006/T007.

Verification: strict config/malformed request denial tests, actual container provisioning/revoke through HTTP ASGI transport, scheduled expiry without explicit sweep calls, actual unavailable-daemon startup followed by readiness recovery, real loopback Uvicorn/HTTPX transport and shutdown cleanup. TLS/live-runtime acceptance remain separate gates. FastAPI recommends lifespan for startup/shutdown: https://fastapi.tiangolo.com/advanced/events/ .
