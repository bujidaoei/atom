# Fixed-profile Docker driver

T005 owns host Docker control only; runtime cannot call it directly. Inputs are the trusted registry Attempt plus constructor-owned broker ID, pinned local image ID and finite profile. The driver computes the exact container name and expected labels; mismatch fails before control operations. It never pulls images, mounts host files/socket, publishes ports or accepts arbitrary Docker flags.

Default files-v1: UID/GID 1000, network none, readonly root, ALL capabilities dropped, no-new-privileges, 256 MiB memory and equal memory-swap (no extra swap), 0.5 CPU, 64 PIDs, 64 MiB workspace tmpfs and 8 MiB temporary tmpfs, nosuid/nodev. Defaults are configurable only through trusted validated constructor profile; workload grants select the named profile, not its values. Image must be sha256 content ID. No platform environment is passed into worker.
Only environment values embedded in the approved immutable image are retained; never use `--env NAME` inheritance. Entrypoint is cleared, fixed absolute Python executable is used, image healthchecks disabled, restart policy no. Images declaring automatic volumes are rejected before creation. Driver validates these effective settings when adopting an existing container.

Create intent must already be committed by registry. Driver checks for an exact existing name and validates owner/attempt/fingerprint/deadline/profile/image and actual limits before reuse. Running owned container is idempotently returned; created container can start; exited/dead container is never silently restarted because tmpfs would be empty. PID 1 is fixed Python code that sleeps only until the absolute attempt deadline, including delayed starts. Create/start response loss is an error requiring lifecycle reconciliation, not blind replacement.
The independent sleep is additionally capped at 7200 seconds even if the Docker host clock is wrong. Precise absolute expiry assumes aligned broker/worker clocks; T006 must enforce broker-side deadlines too, and deployment must check clock synchronization. Observing an exited container while broker clock is just before its deadline is a safe refusal, not permission to restart it.
Only intent/provisioning/ready records may ensure a container; a missing container for an already-ready record is lost state and cannot be silently recreated. The lifecycle layer must supply freshly authorized registry records and serialize operations; the driver cannot detect a stale in-memory Attempt by itself.

Terminate inspects ownership and removes by immutable container ID, then confirms exact name is absent. Daemon error, invalid response or timeout never implies absence. Other owners' containers are never removed. Status/control output is bounded; no workload output is interpreted as control JSON. Control subprocess has finite time and per-stream output caps. Killing the CLI is not evidence of killing the container; callers must reconcile uncertain outcomes.
Termination verifies broker/attempt/grant/deadline identity but permits an old policy digest: configuration upgrades must not make old owned containers impossible to stop. Adoption still requires current exact policy/image/limits. Neither path skips ownership verification.

Fixed file-helper transport now uses bounded stdin in the same subprocess runner: up to 50 MiB request, up to 12 MiB per output stream for binary base64. Control callers retain their 256 KiB default. Concurrent stdin writer/readers must drain or terminate on timeout/overflow; a blocked stdin consumer must not make the runner unbounded. File requests never enter shell/command arguments; only fixed trusted helper source and its validated deadline do. File helper authorization/termination semantics are specified separately in file-operations.md.

Driver integration tests explicitly opt in with ATOM_TEST_DOCKER_IMAGE, use temporary registry and synthetic files, finite containers, no host mounts/network. Verify actual limits, idempotency, wrong owner refusal, peer survival and autonomous deadline exit. No HTTP/grant revocation/in-flight file helper or registry termination acceptance is implied until T006/T007 integration.
