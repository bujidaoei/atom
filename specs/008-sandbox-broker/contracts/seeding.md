# Verified seed lifecycle

Trusted control supplies the verified grant and bounded ATOMSNAP1 bytes. Only a current, unrevoked, unexpired provisioning attempt may import. Source revision must equal immutable grant base_revision. No caller paths, scripts, commands or mounts. Binary input is bounded to 64 MiB file content + 1 MiB manifest + 14 bytes framing; individual files and paths retain snapshot-component limits. Actual tmpfs inode/block overhead can make a logically valid maximum-size archive fail; never report partial import as success.

A fixed helper runs in the inspected owned container as its normal nonroot identity. It holds the workspace directory flock, requires an empty workspace, receives/validates using the existing snapshot implementation into private staging under /workspace, checks the exact expected revision, then moves validated top-level entries into /workspace. Promotion is not an atomic multi-file transaction; isolation comes from provisioning rejecting file operations, lifecycle serialization and retiring the entire attempt on any uncertainty. Staging inside workspace avoids copying across mounts and duplicate data allocation. A 20-second independent alarm bounds stdin/validation/promotion; host CLI has a 25-second bound. Container expiry remains independent.

Only a successful helper response followed by a current-fence/version registry transition admits ready. Late revoke/expiry/version conflict, lost response, failure or process death must not reuse the partially seeded worker. Startup retires prior workers. Calling seed on ready is rejected without mutation; callers resolving lost acknowledgments inspect/provision the same immutable grant and use its durable ready state. No implicit empty seed, automatic reset, arbitrary merge or overwrite of existing workspace.

Seed establishes working input only, not output checkpoint registration. Checkpoint export, conditional control-plane registration, HTTP authorization/body bounds, runtime adapter and production readiness remain separate acceptance gates. This internal component must be tested with actual container bytes and faults, including incorrect revision, malformed streams, preexisting content and failed ready commit.
