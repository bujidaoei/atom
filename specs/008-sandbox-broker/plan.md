## Design
1. Grant codec: fixed HS256, explicit type/issuer/audience, strict bounded JSON schema, integer times/fence, logical IDs only, SHA-256 input revision and files-v1 capability. Dedicated random 32+ byte signing key held by trusted control plane and broker, never runtime/workload. Broker is trusted to mint with this shared key; stronger signing separation/key rotation is future hardening. Token verification alone does not implement revocation or authorization admission.
2. Host-local SQLite registry with explicit versioned schema/bootstrap, transactional create intent, unique grant ID/attempt, canonical claim digest, state/fence/deadline and owned container name. Persist revocation, operation intent and termination status. Schema v2 migrates exact v1 atomically and adds durable orphan observations before removal; full-ID ownership reinspection and confirmed absence close recovery, including process death between removal and confirmation. Single broker process owns dispatch; restart reconciles before readiness. This is not the distributed queue or HA database.
3. Docker driver uses fixed approved image digest/profile; no caller-selected mounts/flags/env. Bounded subprocess IO/timeouts, labelled ownership, independent lifetime, nonroot/read-only/drop-cap/no-network/tmpfs limits. Registry controls all operations. Uncertain creation/termination goes through reconciliation, no blind retry or local fallback.
4. Typed file-helper operations: current shell-shaped SandboxClient cannot safely be treated as arbitrary shell authorization. Add structured workspace-operation port and update own wrappers/adapter together; broker maps operations to fixed helper programs. Retain exact pagination/write/edit behavior and tool names. No command string allowlist guessing. Fixed Linux file_helper.py executes only validated operations via file_ops.py, uses descriptor-relative paths, workspace flock/conditional writes, bounded stdin/output and independent alarm; runtime migration/HTTP authorization is subsequent work per contracts/file-operations.md.
5. Explicit checkpoint path freezes broker operation admission, waits for active helper termination, exports while container alive, verifies snapshot and conditionally registers current fence. Destroy only cleans. Recovery seeds new attempts from last registered snapshot; preview reads committed revision.
6. HTTP boundary: separate administrative service credential for control-plane admission/revocation/checkpoint transfer; runtime presents bearer grant for scoped file/status/release operations only. Bounded request/stream deadlines. Standalone config/service and loopback-only entry point expose implemented operations under contracts/service.md and runtime-http.md; lifespan schedules recovery and confirmed normal-shutdown cleanup. Production readiness requires broker and reconciliation; migration keeps old data until verified import and pointer switch. API-database registration and production orchestration are not performed by broker HTTP.

It validates export byte/semantic digests and confirms only a matching trusted API receipt. No automatic replay follows unknown outcomes. The real Linux registration harness uses this client over Uvicorn and now commits API reservation before target-worker provisioning, reconstructs the exact grant after process loss, binds the observed broker ID before seed and consumes a real database receipt. Confirmation echoes a bounded archive for byte verification and represents a trusted control-plane registration assertion, not an independent API-database commit. Checkpoint acknowledgement continuation: trusted Lifecycle.confirm_checkpoint is used after the coordinator has a durable API receipt. Revision repository continuation: backend/app/revisions.py consumes explicit schema v1, immutable-storage descriptors and trusted termination observations. Artifact prerequisite: backend/app/artifacts.py stores verified archives in a private Linux directory using exclusive stages, file fsync, no-overwrite publication and directory fsync. Exact-byte artifact keys differ from semantic manifest revisions. Finite flock and bounded recovery scan preserve completed objects across interrupted writes; one scan slot is reserved for staging recovery. Existing-object confirmation also fsyncs the file and directory. This is a tested local implementation, not HA/encryption/backup acceptance or control-plane revision registration. Versioned API migration/ownership requirements are now specified in contracts/revision-registration.md, including separate race/main workspace heads.

Checkpoint export continuation: reuse the existing Linux snapshot exporter in a fixed flock/alarm helper and add host-side verify_snapshot without materializing files. Driver stdout permits the bounded archive size only when explicitly requested; other callers retain their smaller output limits. Lifecycle holds serialization and persists quiescing before export, rechecks grant/version after verification, and returns bounded bytes without marking checkpointed. This avoids introducing host crash-orphan directories before durable artifact/registration design. Read-only re-export is safe for an unchanged quiesced worker. Storage, registration and runtime completion ordering remain T009.

Runtime adapter continuation: BrokerSandboxClient consumes a trusted ready lease, verifies live scoped status, uses bounded nonredirecting HTTP and unique per-invocation operation IDs, validates responses/integrity, rejects shell and local fallback, and confirms release through a scoped endpoint. Revoked grants may repeat only cleanup of their exact immutable attempt; expired grants require existing administrative reconciliation. Actual Pi tools run through a loopback broker test harness. Production control-plane grant/seed orchestration and selection are not implemented by this adapter.

HTTP continuation: expose implemented administrative seed and grant-scoped file operations per contracts/runtime-http.md. A shared asyncio transfer lock bounds concurrent large-body intake and response serialization to one in this single-process profile. Revocation bypasses that lock. Strict envelopes/media types/stream limits precede helper dispatch; ownership is checked before intake and within lifecycle. Authorize provisioning via a read-only registry check so invalid seed requests cannot create attempt intent. Runtime client and production control-plane wiring remain subsequent work.

Seed prerequisite: implement the bounded internal provisioning→ready path before exposing runtime file HTTP operations. Reuse the existing snapshot decoder inside the inspected container, stage under the empty workspace tmpfs, verify base revision and promote while dispatch remains unavailable. Commit ready only after current ownership/version checks; retire uncertain imports. This completes neither output checkpoint registration nor the rest of T009. Driver stdin capacity includes the full 65-MiB-plus-framing snapshot bound; text file helper limits remain unchanged. Independent helper alarm 20 seconds, CLI bound 25 seconds; memory stays bounded but is not streaming admission at the future HTTP boundary.

Operation receipt continuation: schema v3 migrates exact v1/v2 transactionally. Lifecycle admits a durable running receipt before helper execution, reauthorizes before effects and completion, caches bounded completed results, and retires uncertain attempts without replay. Revocation persists even while the control lock is occupied and invalidates outstanding receipts. Contract: contracts/operation-receipts.md. HTTP exposure and production snapshot-seeded ready transitions remain dependent work.

Grant validation → registry/reconciliation → Docker/file helpers → HTTP and structured runtime adapter → snapshot registration/migration → real fault/acceptance. Do not expose incomplete endpoints. Grant library can be tested independently while remaining tasks stay open.
